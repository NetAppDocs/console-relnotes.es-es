==== Mejoras en cargas de trabajo de Kubernetes

En esta versión, NetApp Backup and Recovery presenta las siguientes mejoras para las cargas de trabajo de Kubernetes:

* *Trident Protect 26.10*: Esta versión incluye Trident Protect 26.10.
* *compatibilidad con los controladores ontap-nas-economy y ontap-san-economy*: ahora puedes proteger las reclamaciones de volumen persistente (PVC) aprovisionadas por el controlador Trident de NetApp `ontap-nas-economy` (Qtrees) y por el controlador `ontap-san-economy` (LUNs). Cuando proteges PVC con controladores economy, proteges por completo el FlexVol o la LUN subyacentes. Puedes restaurar PVC individuales desde estas copias de backup.
* *Alertas compatibles con Kubernetes*: ahora las alertas se envían una vez por cada aplicación de Kubernetes, en lugar de una vez por cada volumen.
* *Compatibilidad con instantáneas de grupos de volúmenes*: ahora puedes crear grupos de volúmenes al definir una aplicación de Kubernetes. Los grupos de volúmenes te permiten crear instantáneas de varios volúmenes a la vez como un conjunto coherente tras fallos, lo que garantiza la coherencia de los datos en todos los volúmenes del grupo.
* *Compatibilidad con el almacenamiento de objetos compatible con S3*: ahora puedes realizar copias de seguridad de los recursos y datos de las aplicaciones de Kubernetes en un almacenamiento de objetos compatible con S3 añadiendo las credenciales del destino de la copia de seguridad y configurando las políticas de protección.


Para obtener más información sobre cómo proteger las cargas de trabajo de Kubernetes, consulta https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["Descubre cómo proteger las cargas de trabajo de Kubernetes con NetApp Backup and Recovery"^].



==== Mejoras en las cargas de trabajo de ONTAP Volumes

En esta versión, NetApp Backup and Recovery presenta las siguientes mejoras para las cargas de trabajo de ONTAP Volumes:

* *Informes de protección*: NetApp Backup and Recovery ahora admite crear y descargar informes ampliados para cargas de trabajo de ONTAP Volumes.
* *Conservar las copias de seguridad al anular el registro de un sistema ONTAP*: cuando anulas el registro de un sistema ONTAP de NetApp Backup and Recovery, ahora puedes elegir entre descartar los datos de las copias de seguridad realizadas anteriormente o mantenerlos disponibles para restaurarlos. La documentación de NetApp Backup and Recovery ahora incluye instrucciones para usar la CLI de ONTAP para restaurar los datos conservados después de anular el registro del sistema.


Para obtener más información, consulta https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-backup-manage.html#unregister-netapp-backup-and-recovery-for-a-system["Anula el registro de Backup and Recovery para un sistema"^].

Para obtener más información sobre la protección de las cargas de trabajo de ONTAP Volumes, consulta https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["Descubre la protección de volúmenes de ONTAP con NetApp Backup and Recovery"^].



==== Mejora de las cargas de trabajo de Oracle Database

En esta versión, NetApp Backup and Recovery presenta la siguiente mejora para las cargas de trabajo de Oracle Database:

*Restaurar en una ubicación alternativa*: NetApp Backup and Recovery ahora permite restaurar una base de datos Oracle en una ubicación alternativa (un host registrado diferente).

Para obtener detalles sobre cómo proteger las cargas de trabajo de Oracle Database, consulta https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-oracle-protect-overview.html["Descubre cómo proteger las cargas de trabajo de Oracle Database con NetApp Backup and Recovery"^].

=== Resiliencia frente al ransomware



==== Configuración mejorada del entorno de recuperación aislado

Ransomware Resilience ahora proporciona un flujo de trabajo mejorado para la configuración de entornos de recuperación aislados. El nuevo flujo de trabajo aclara y simplifica el proceso para configurar un entorno de recuperación aislado para entornos de cloud o on-premises.

Para obtener más información, consulta link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-clean-restore.html["Crea un entorno de recuperación aislado para hacer una restauración limpia"^].



==== Flujo de trabajo mejorado para activar la supervisión de la actividad de los usuarios

Ransomware Resilience ha mejorado el flujo de trabajo para habilitar la supervisión de la actividad de los usuarios. Antes, Ransomware Resilience comprobaba la conexión del recopilador de datos cada vez que habilitabas una estrategia de protección contra ransomware con supervisión de la actividad de los usuarios en una carga de trabajo. Con esta actualización, esa comprobación ahora se omite si existe un recopilador de datos para la VM de almacenamiento y está en estado "running", lo que agiliza el flujo de trabajo de protección.

Para obtener más información, consulta link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-use-protect.html["proteger las cargas de trabajo"^].



==== El nivel de servicio Flex de Google Cloud NetApp Volumes ya está disponible de forma general

Ya está disponible de forma general (GA) la compatibilidad con el nivel de servicio Flex de Google Cloud NetApp Volumes en Ransomware Resilience.

=== Cloud Volumes ONTAP



==== Cloud Volumes ONTAP 9.19.1 en Azure

Ya puedes usar NetApp Console para implementar y gestionar la versión de disponibilidad general (GA) de Cloud Volumes ONTAP 9.19.1 en Azure.

Console es compatible con Cloud Volumes ONTAP 9.19.1 en AWS y Google Cloud desde agosto de 2026.

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Notas de la versión de Cloud Volumes ONTAP 9.19.1"^]



==== Cifrado de Azure en el host para Cloud Volumes ONTAP

A partir de Cloud Volumes ONTAP 9.19.1 GA, el cifrado de Azure en el host está habilitado de forma predeterminada para las nuevas implementaciones de Azure de un solo nodo y de alta disponibilidad (HA) que cumplan los requisitos previos. Esta función cifra los datos del servidor físico que aloja la VM, incluidos el disco efímero y las cachés asociadas a nivel de host, a medida que los datos se escriben y se leen desde el host.

Antes de implementar Cloud Volumes ONTAP en Azure, comprueba que tu entorno cumpla los siguientes requisitos previos:

* La función `EncryptionAtHost` está registrada para tu suscripción a Azure. Consulta https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Documentación de Microsoft: activar el cifrado en el host"^].
* El tipo de instancia de VM que has seleccionado admite el cifrado en el host en tu región de Azure. Consulta https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Documentación de Microsoft: cómo encontrar los tamaños de máquinas virtuales compatibles"^].


Ten en cuenta estos puntos:

* No se requiere ninguna configuración adicional.
* Si no se cumplen estos requisitos previos, el cifrado de Azure en el host no estará habilitado para tu implementación de Cloud Volumes ONTAP.
* El cifrado en el host solo se aplica a Azure, no a AWS ni a Google Cloud.


Documentación de Microsoft: https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["Utiliza Azure portal para habilitar el cifrado de extremo a extremo mediante encryption at host"^]



==== Cifrado de red del backend en clústeres de Cloud Volumes ONTAP en Azure y Google Cloud

Cloud Volumes ONTAP 9.19.1 y versiones posteriores admiten el cifrado de la red del clúster de backend para configuraciones de alta disponibilidad (HA) en Azure y Google Cloud.

La activación del cifrado de red del clúster podría afectar al rendimiento del clúster. Actúa con precaución y comprueba que tu entorno pueda soportar la sobrecarga adicional antes de habilitar esta función.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["Activa el cifrado de red del backend en los clústeres de Cloud Volumes ONTAP"^]



==== Capacidad para reducir las interrupciones durante el mantenimiento programado de Azure

Durante el mantenimiento programado, Azure puede pausar brevemente una VM en un par de HA de Cloud Volumes ONTAP. ONTAP podría interpretar la pausa como una caída de nodo y mover las operaciones de almacenamiento al nodo asociado, y luego devolverlas cuando la VM se reanude (takeover and giveback). Este proceso puede interrumpir las conexiones activas de los clientes, incluso cuando no haya ningún fallo de nodo.

Con Cloud Volumes ONTAP 9.19.1 y versiones posteriores, puedes activar una configuración opcional que permite que el par de HA siga funcionando durante una congelación por mantenimiento programado de Azure sin iniciar automáticamente la toma de control automática ni la devolución.


NOTE: Esta función está disponible como vista previa pública con Cloud Volumes ONTAP 9.19.1.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["Evita interrupciones durante el mantenimiento de Azure para los pares de HA de Cloud Volumes ONTAP"^]

=== Recuperación ante desastres



==== Orden de arranque opcional para los grupos de recursos de Kubernetes

NetApp Disaster Recovery ahora admite la configuración de un orden de arranque opcional para los grupos de recursos en un plan de replicación de Kubernetes, al especificar un orden de prioridad y un tiempo de retraso opcional para los recursos. Esta opción te permite arrancar recursos al mismo tiempo cuando sea necesario y retrasar el arranque de los recursos que dependen de otros, lo que ayuda a que tus aplicaciones vuelvan a estar en línea de forma correcta.

Para obtener más información, consulta link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/task-replication-plan-kubernetes.html["crear un plan de replicación"^].

Disaster Recovery ahora es compatible con volúmenes de SnapLock, lo que te permite realizar una conmutación por error de instantáneas a prueba de manipulaciones.. Al realizar una conmutación de vuelta con volúmenes de SnapLock, debes usar la opción *Take snapshot now* para garantizar que la conmutación de vuelta se complete correctamente.

Para obtener más información, consulta las instrucciones para link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["conmutación por error"^] y link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failback.html["conmutación por recuperación"^].

Las ejecuciones de actualización de vCenter, los planes de replicación y el cumplimiento normativo se han simplificado en una única tarea para facilitar una ejecución más rápida. Para ver este cambio, descubre cómo link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["supervisar trabajos"^].



==== Comprobaciones de cumplimiento de Kubernetes

Disaster Recovery ha añadido comprobaciones de cumplimiento para identificar entornos de trabajo que faltan para las cargas de trabajo de Kubernetes. Estas comprobaciones de cumplimiento ayudan a garantizar el buen estado de las cargas de trabajo y la integridad de tus planes de replicación.

==== Mejoras en las cargas de trabajo de ONTAP Volumes

En esta versión, las cargas de trabajo de ONTAP Volumes incorporan las siguientes mejoras en fase de vista previa:

* *Compatibilidad mejorada para dark sites*: NetApp Backup and Recovery para dark sites ahora ofrece las mismas capacidades de protección de datos de ONTAP Volumes que NetApp Backup and Recovery. Esta mejora incluye servicios actualizados de copia de seguridad, restauración y gestión de trabajos, así como una nueva base de datos de metadatos. Durante una actualización, los datos existentes de la base de datos se conservan y se migran automáticamente. Después de la actualización, revisa los registros de auditoría para verificar que la migración se completó correctamente. NetApp Backup and Recovery para dark sites solo admite cargas de trabajo de ONTAP Volumes.
* *Cancelar trabajos de restauración de volúmenes*: ahora puedes cancelar trabajos de restauración de ONTAP Volumes en curso desde la página de supervisión de trabajos, lo que facilita la gestión de los trabajos de larga duración o de los que se ejecutan con lentitud.
* *Mejora en los informes del estado de indexación de volúmenes*: El panel de control de ONTAP Volumes ahora informa del estado de indexación con más precisión al introducir el estado  `Not Applicable` para los volúmenes y las copias de Snapshot que no son aptos para la indexación. El estado  `Not Indexed` ahora se reserva para los volúmenes que están esperando a ser indexados, y los detalles del volumen ahora muestran el estado de indexación por Snapshot con un texto al pasar el cursor que explica por qué un volumen o una copia de Snapshot no se indexará.
* *Compatibilidad con AFX de NetApp*: ahora puedes proteger volúmenes alojados en clústeres AFX de NetApp de 2 y 4 nodos.


Para obtener más información sobre la protección de las cargas de trabajo de ONTAP Volumes, consulta https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["Descubre la protección de volúmenes de ONTAP con NetApp Backup and Recovery"].



==== Mejoras en cargas de trabajo de Kubernetes

En esta versión, las cargas de trabajo de Kubernetes introducen las siguientes mejoras:

La clasificación de datos incluye ahora una pestaña *Escaneos activos* en el menú de configuración, lo que ofrece una experiencia mejorada para gestionar los escaneos. La pestaña *Escaneos activos* ofrece una visión general de todos los volúmenes que has activado para su escaneo, con filtros habituales para ordenar tus recursos. La pestaña también proporciona una ubicación central para priorizar escaneos, pausarlos y revisar errores.

Para obtener más información, consulta link:https://docs.netapp.com/us-en/data-services-data-classification/task-managing-repo-scanning.html["Gestiona escaneos"^].



[[disaster-recovery]]
=== Recuperación ante desastres



==== Panel de control mejorado

El panel de control de Disaster Recovery se ha actualizado con una experiencia mejorada que ofrece una visión global y de un solo vistazo de todo tu entorno de Disaster Recovery. El nuevo panel de control incluye:

* *Visibilidad unificada de las cargas de trabajo* — supervisa tanto las cargas de trabajo de VMware como las de Kubernetes junto con el estado de la infraestructura subyacente desde un único panel de control.
* *Detección proactiva de incidencias* — El panel de control ahora destaca automáticamente las incidencias relacionadas con el entorno, lo que permite un diagnóstico más rápido y reduce el tiempo necesario para resolverlas.
* *Uso de la capacidad* — Las métricas de capacidad ahora se presentan directamente en el panel de control, lo que facilita entender el consumo de recursos.


Para más información, consulta link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/dashboard-view.html["Consulta el estado de salud de tus planes de NetApp Disaster Recovery en el panel de control"^].



==== Informes mejorados

Se han ampliado las funciones de generación de informes para ofrecer una visión más detallada de las actividades de NetApp Disaster Recovery en todo tu entorno:

* Genera informes centrados en cargas de trabajo de VMware, de Kubernetes o en ambas, lo que te ofrece la flexibilidad necesaria para adaptar los informes a tu público.
* Cada informe ofrece un resumen completo de la actividad durante un periodo de tiempo determinado, lo que garantiza una visibilidad total de los eventos que tienen lugar en tu entorno de NetApp Disaster Recovery.


Para más información, consulta link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/reports.html["Crea informes de NetApp Disaster Recovery"^].



==== Registro de tareas de los usuarios

Disaster Recovery ha mejorado la rendición de cuentas y la auditabilidad de los trabajos gracias al registro de trabajos a nivel de usuario. Ahora, cada trabajo ejecutado registra el usuario que lo inició, lo que proporciona un registro de auditoría claro con fines de cumplimiento y resolución de problemas. Los trabajos activados automáticamente por Disaster Recovery se identifican como "system", lo que facilita distinguir entre la actividad iniciada por el usuario y la iniciada por el servicio.

Para más información, consulta link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["Monitoriza los trabajos de NetApp Disaster Recovery"^].



==== Rendimiento y optimización de recursos

Se han realizado varias mejoras internas para reducir el consumo general de recursos del sistema y aumentar el rendimiento en todas las operaciones de NetApp Disaster Recovery.

[[cloud-volumes-ontap]]
=== Cloud Volumes ONTAP



==== Integración de Cloud Volumes ONTAP con Microsoft OneLake

Cloud Volumes ONTAP ya admite la integración con link:https://learn.microsoft.com/en-us/fabric/onelake/onelake-overview["Microsoft OneLake"^] en versión preliminar pública. Puedes integrar Cloud Volumes ONTAP con link:https://community.fabric.microsoft.com/["Microsoft Fabric"^] usando link:https://learn.microsoft.com/en-us/fabric/onelake/onelake-overview["Microsoft OneLake"^] para que los datos NAS existentes de Cloud Volumes ONTAP estén disponibles para los servicios de análisis y de IA de Microsoft, como Power BI, Azure AI Search, OpenAI y Microsoft Copilot. La integración no requiere movimiento ni duplicación de datos. La integración usa el acceso de link:https://docs.netapp.com/us-en/ontap/s3-multiprotocol/index.html["ONTAP S3 multiprotocolo"^] para conectar Cloud Volumes ONTAP a un lakehouse de Microsoft Fabric ya existente.

==== Corregir, descartar y reactivar configuraciones de Cloud Volumes ONTAP en Microsoft Azure

El panel bien estructurado en la NetApp Console ahora te permite corregir las recomendaciones de configuración para tus sistemas Cloud Volumes ONTAP.

También puedes excluir una o varias configuraciones del análisis de well-architected. Esto te permite ignorar configuraciones específicas que no se aplican a tu entorno.

Si deseas incluir más adelante una configuración que hayas descartado, puedes reactivarla en el panel de control de well-architected. Esto restaura la configuración en el análisis y te permite obtener recomendaciones y soluciones para ella.

* link:https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-improve-configurations-cvo.html["Corregir, descartar y reactivar configuraciones de Cloud Volumes ONTAP en Microsoft Azure"^]
